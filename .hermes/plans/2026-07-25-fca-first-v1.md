# FCA-first v1 implementation plan

## Safety contract

- Preserve migrations 001–005 byte-for-byte; add append-only migrations only.
- Keep all delivery manual. Do not add a send method, route, command, worker, or autonomous drafting path.
- Keep Gmail drafting fail-closed (`LINT_NOT_READY`) in production.
- Treat FCA, Companies House, and website content as untrusted data behind bounded, allowlisted transports.
- Discovery records are not leads. Only active incorporated Companies House evidence may promote a firm.
- Evidence must be source-linked, timestamped, hashed, and honest about unknown/failure states.
- Outreach readiness is fail-closed and requires a passing, current QC result plus explicit human approval.
- Keep operational data/PII in the private SQLite database; vault output is sanitised only.

## Vertical TDD slices

1. Add migration 006 for FCA firms, immutable observations, enrichment runs/evidence, QC runs, and human review state. Prove upgrade from migration 005 and direct-SQL constraints first.
2. Add bounded FCA discovery parser/transport and idempotent staging. Test allowlist, no redirects, timeout, size/content type, malformed rows, deterministic limits, unchanged retries, and changed evidence history.
3. Add FCA-to-Companies-House verification/promotion service using the existing minted receipt boundary. Test active incorporated success and fail-closed missing/mismatched evidence with fakes only; live Companies House remains credential-gated.
4. Add bounded website transport plus pluggable accountability, AI-exposure, and governance-gap signal scanners. Persist exact evidence and score 0–100/HOT-WARM-COOL with unknown states.
5. Add repeatable QC for failed scans, duplicates, dead/redirected sites, stale/changed/contradictory/missing evidence. Prove that bad or unapproved records cannot become outreach-ready.
6. Replace LCA operator behaviour with FCA CLI commands and a repository-backed FCA `/today` review surface. Add approve/reject controls, notes/reasons, evidence/source links, score/temperature, QC state, CSRF and Host checks.
7. Retire operational LCA rows transactionally after backup; retain migration 005 and a sanitised audit record in application storage. Verify candidates/leads/sends counts and integrity.
8. Update docs and package data. Run focused and full verification, exact-tree independent review, commit/push/PR/merge, deploy private Tailscale service, and health-check.
9. Write a dated sanitised completion/deployment note to Jarvis inbox covering `leads.misegroup.co.uk`, managed access control, HTTPS, sessions, CSRF/Host, binding/proxy, secrets, DNS/TLS, rollback, and staged Tailscale migration.
